### 1. ROME — MLP-as-associative-memory, constrained least-squares statement
- **statement**: The transformer MLP's down-projection weight matrix W is viewed as a linear associative memory mapping keys K to values V. To insert one new key-value pair (k*, v*) while disturbing existing memories as little as possible, ROME solves a least-squares problem constrained to satisfy the new association exactly. The closed-form solution is a rank-one update to W.
- **equation_verbatim**: minimize ||Ŵ K − V|| such that Ŵ k∗ = v∗   by setting Ŵ = W + Λ(C^{-1}k∗)^T.   (2)
- **symbols**: W = original (pretrained) weight matrix of the MLP down-projection layer; K = [k1|k2|...] = matrix of pre-existing key vectors (stacked as columns); V = [v1|v2|...] = matrix of pre-existing value vectors; Ŵ = the new (edited) weight matrix; k* ∈ R^d = the new key vector representing the subject; v* ∈ R^d = the new value vector representing the target fact; C = KK^T = uncentered covariance (second-moment) of the pre-existing keys, precached from a Wikipedia sample; Λ = a vector proportional to the residual error of the new pair on the original memory (defined in eq. 17 below); ||·|| = the induced (here Frobenius, per Appendix A) matrix norm.
- **assumptions**: W is assumed to already be the (least-squares-)optimal solution for the pre-existing key/value pairs K, V (i.e. it satisfies the normal equation W K K^T = V K^T). C = KK^T is assumed nondegenerate (invertible) so that C^{-1} exists. The layer is treated as a single linear map (the nonlinearity/layernorm of the MLP is abstracted away at this point — k* and v* are read/written at the linear projection).
- **derivation_steps**: Source gives the closed form directly in the main text (Eq. 2) citing Bau et al. (2020) for the associative-memory framing, and states 'full derivation in Appendix A.' The full derivation (Appendix A, verbatim, is captured in the next item) proceeds via a Lagrangian on the constrained least-squares problem.
- **worked_numbers**: none in this main-text statement (see Appendix A item for the algebraic path and the covariance-estimation item for concrete sample sizes)
- **source**: meng-rome-2022.pdf
- **locator**: §3.1, p.4 (Eq. 2); Meng, Bau, Andonian, Belinkov, 'Locating and Editing Factual Associations in GPT,' NeurIPS 2022

[constraint to solve for Ŵ:]   Ŵ k∗ = v∗                          (7)
define L(Ŵ, Λ) = (1/2)||ŴK − V||_F^2 − Λ^T(Ŵk∗ − v∗)              (8)
= (1/2)(ŴK)(ŴK)^T − V(ŴK)^T + (1/2)VV^T − Λ^T(Ŵk∗ − v∗)          (9)
setting  0 = ∂L/∂Ŵ = Ŵ(KK^T) − VK^T − Λk∗^T                       (10)
ŴKK^T = VK^T + Λk∗^T                                               (11)
[subtracting Eq.6 from Eq.11:]  (Ŵ − W)KK^T = Λk∗^T                (12)
Ŵ = W + Λ(C^{-1}k∗)^T                                              (13)
[defining uT = (C^{-1}k∗)^T ∈ R^D:]  ŴI − Λu^T = W                 (14)
[block linear system for Ŵ, Λ jointly:]
[ Ŵ  Λ ] [ I    k∗ ]  = [ W   v∗ ]
           [ −u^T  0  ]                                             (15)
[substituting Eq.13 into Eq.7:]
Ŵk∗ = (W + Λu^T)k∗ = Wk∗ + Λ(u^Tk∗) = v∗                            (16)
Λ = (v∗ − Wk∗)/(u^Tk∗) = (v∗ − Wk∗)/((C^{-1}k∗)^Tk∗)                (17)
- **symbols**: W, Ŵ, K, V, k*, v*, C = KK^T as above; Λ ∈ R^H is the Lagrange multiplier vector (H = output/value dimension); L(Ŵ,Λ) is the Lagrangian; I is the identity matrix; u^T ≜ (C^{-1}k∗)^T ∈ R^D is a row vector (D = key/input dimension); the block matrix in Eq. 15 stacks the stationarity condition (Eq. 14) and the constraint (Eq. 7) so Ŵ and Λ can be solved simultaneously.
- **assumptions**: Same as the main-text item: W solves the unconstrained normal equations for the pre-edit K,V; C = KK^T is nondegenerate and symmetric (symmetry of C is explicitly invoked when going from Eq. 12 to Eq. 13, so that Λk∗^T = Λ(C^{-1}k∗)^T·C can be rearranged as stated). The Frobenius norm is used because the optimization variable is a matrix, not a vector, unlike 'the classical textbook presentation of least squares.'
- **derivation_steps**: Source gives every algebraic step explicitly (this is one of the few fully-worked derivations across all 8 papers): (1) write the unconstrained normal equations (Eq. 6) that W satisfies; (2) form the Lagrangian of the constrained problem (Eq. 8-9, expanding the Frobenius-norm term); (3) take ∂L/∂Ŵ = 0 to get the stationarity condition (Eq. 10-11); (4) subtract the original (unconstrained) normal equation from the new stationarity condition — 'most terms cancel' — leaving the rank-one correction (Ŵ−W)KK^T = Λk*^T (Eq. 12); (5) define C ≜ KK^T, invert (nondegeneracy assumption), and use symmetry of C to write Ŵ = W + Λ(C^{-1}k*)^T (Eq. 13); (6) substitute this Ŵ back into the original constraint Ŵk*=v* to solve explicitly for Λ (Eq. 16-17), or equivalently write the block linear system (Eq. 15) that solves for Ŵ and Λ jointly.
- **worked_numbers**: none (this is a pure algebraic derivation with no numeric instantiation in Appendix A itself)
- **source**: meng-rome-2022.pdf
- **locator**: Appendix A 'Solving for Λ Algebraically,' p.14 (Eqs. 5-17)

### 3. ROME — key selection (k*) and value optimization (v*) objective
- **statement**: k* is constructed as the average MLP-hidden-state activation (after the nonlinearity) at the last subject token, averaged over several random prefix contexts, to make the lookup key robust to context. v* is not read off an activation directly; it is found by gradient-based optimization of an objective balancing (a) driving up the probability of the target object and (b) a KL-divergence penalty that discourages drift in the model's other beliefs about the subject.
- **equation_verbatim**: k∗ = (1/N) Σ_{j=1}^{N} k(x_j + s),  where  k(x) = σ(W_fc^{(l∗)} γ(a^{(l∗)}_{[x],i} + h^{(l∗−1)}_{[x],i}))     (3)

v∗ = argmin_z L(z),  where
L(z) = (1/N) Σ_{j=1}^{N} [ −log P_{G(m_i^{(l∗)}:=z)}[o∗ | x_j + p] ]_(a)  +  [ D_KL( P_{G(m_i^{(l∗)}:=z)}[x | p'] ‖ P_G[x | p'] ) ]_(b)     (4a,4b)
- **symbols**: N = number of sampled prefix texts (50 in practice, per §E.5); x_j = a randomly generated prefix token sequence; s = the subject text; l* = the target (mid-range) layer chosen for the edit; i = the last subject-token index; σ = the MLP nonlinearity; W_fc^{(l*)} = the fan-out (first) MLP weight matrix at layer l*; γ = layernorm; a^{(l*)}_{[x],i}, h^{(l*−1)}_{[x],i} = attention output and residual-stream hidden state feeding into the MLP; z = the candidate value vector being optimized; m_i^{(l*)} := z denotes hooking/substituting z as the MLP output at token i, layer l*; G(m_i^{(l*)}:=z) = the model executed with that substitution; o* = desired target object; p = the factual prompt (e.g. 'The Space Needle is located in the city of'); p' = a second prompt of the form '{subject} is a', used to probe the model's 'essence' beliefs about the subject; D_KL = Kullback-Leibler divergence.
- **assumptions**: The optimization does not alter model weights directly — it identifies a representation-space vector v* to be later inserted algebraically via Eq. 2/13. k* averaging over multiple xj is meant to make the lookup key robust across different contexts in which the subject could appear.
- **derivation_steps**: Source states the construction directly (not derived from a deeper principle) — it is a design choice justified by ablations (Appendix E.5: no-prefix baseline S0=86.1 vs. with-prefix S=89.2; longer/more prefixes did not help much, S0=89.3 and 89.2 respectively).
- **worked_numbers**: N=50 random prefix sequences of length 2-10 (main text); Appendix E.5 specifies 20 texts split as ten of length 5 + ten of length 10 for the actual k* computation reported; ablation: no-prefix S0=86.1 vs S=89.2 (with prefixes); longer prefixes (10×5 + 10×10 + 10×50) → S0=89.3; more same-length prefixes (30×5+30×10) → S0=89.2. Value optimization: Adam, lr=0.5, weight decay 1.5×10^-3, KL scaling λ=1×10^2, max 20 steps, early-stop at L(z) ≤ 5×10^-2. Edit takes ≈2s on an NVIDIA A6000 for GPT-2 XL.
- **source**: meng-rome-2022.pdf
- **locator**: §3.1 Step 1-2, p.5 (Eqs. 3-4); Appendix E.5, p.26

### 4. ROME — second-moment (covariance) statistic C estimation protocol
- **statement**: C = KK^T (equivalently, C ∝ E[kk^T]) is not computed from the model's actual pretraining keys (inaccessible), but estimated empirically as the uncentered covariance of MLP-input activations sampled broadly from Wikipedia text — over every token position, not just subject tokens.
- **equation_verbatim**: Second moment statistics: C ∝ E[kk^T] (stated in prose, §3.1 and §E.5; not given a separate tag)
- **symbols**: C = KK^T; k = MLP fan-out hidden-state activation vector at a given token; E[·] = expectation over the sampling distribution (Wikipedia tokens).
- **assumptions**: Assumes the true pretraining key distribution can be approximated by a large i.i.d.-like sample of hidden states drawn from Wikipedia text (2020-05-01 snapshot) — i.e. that this text sample is representative of 'the previously stored memories' the edit must avoid disturbing.
- **derivation_steps**: source states without derivation — this is an empirical estimation procedure, not an algebraic derivation. The procedure: sample random Wikipedia articles without replacement; run each through the transformer up to its buffer length; collect the fan-out MLP activation k for EVERY token (not just special/subject words) at float32 precision; repeat until 100,000 k vectors collected; compute the second-moment statistic from this sample.
- **worked_numbers**: 100,000 samples of hidden states k; collected from Wikipedia 2020-05-01 snapshot; float32 precision; edit performed at layer 18 for their reported experiments (chosen as the causal-effect peak from Fig. 1k / Fig. 3).
- **source**: meng-rome-2022.pdf
- **locator**: §3.1 p.5 ('C is a constant that we pre-cache...'); Appendix E.5 p.26 'Second moment statistics'

### 5. MEMIT — transformer decoder and residual-stream decomposition (preliminaries)
- **statement**: MEMIT's derivation starts from the standard pre-norm transformer decoder recursion, writing attention and MLP as parallel additive contributions to the residual stream, then unrolling the recursion to show the final hidden state as a sum of the embedding plus every layer's attention and MLP outputs — this is what licenses 'spreading' an edit's needed change across multiple MLP layers rather than storing it all in one.
- **equation_verbatim**: P(x^[t] | x^[1],...,x^[E]) ≜ G([x^[1],...,x^[E]]) = softmax(W_y h^D_[E])            (1)
h^l_[t](x) = h^{l−1}_[t](x) + a^l_[t](x) + m^l_[t](x)                                (2)
where a^l = attn^l(h^{l−1}_[1], h^{l−1}_[2], ..., h^{l−1}_[t])                        (3)
m^l_[t] = W^l_out σ(W^l_in γ(h^{l−1}_[t]))                                            (4)
E = {(s_i, r_i, o_i) | i}  s.t.  ∄i,j. (s_i=s_j) ∧ (r_i=r_j) ∧ (o_i≠o_j)              (5)
h^L_i = h^0_i + Σ_{l=1}^{L} a^l_i + Σ_{l=1}^{L} m^l_i                                 (6)
- **symbols**: D = number of transformer layers; h^l_[t] = residual-stream hidden state at layer l, token position t; a^l = attention module output at layer l; m^l = MLP module output at layer l; W_y = unembedding matrix; γ = layernorm; σ = MLP nonlinearity; W^l_in, W^l_out = MLP fan-in/fan-out weight matrices at layer l; h^0_[t] = token embedding; E = the set of requested edits (subject s, relation r, object o) with a no-conflict logical constraint; hL_i, a^l_i, m^l_i (in Eq. 6) abbreviate the last-subject-token (position S) versions h^L_[S](p_i), a^l_[S](p_i), m^l_[S](p_i) for edit example i.
- **assumptions**: Attention and MLP are written 'in parallel' (both read the same pre-layernorm residual-stream state and both add back into it independently), following the GPT-J/GPT-NeoX parallel-block convention (Black et al. 2021; Wang & Komatsuzaki 2021) — this is a specific architectural assumption, not universal to all transformers.
- **derivation_steps**: Eq. 6 is obtained by直接 unrolling the recursion of Eq. 2 from layer 0 to layer L (source states this as 'Unrolling Eqn. 2' with no further intermediate algebra shown — it is a straightforward telescoping sum).
- **worked_numbers**: none in this section (architectural/definitional)
- **source**: meng-memit-2023.pdf
- **locator**: §3 'Preliminaries: Language Modeling and Memory Editing,' p.2-4 (Eqs. 1-6)

### 6. MEMIT — single-layer batch optimal update (normal equation)
- **statement**: Before deriving the batched-insertion update, MEMIT restates the single-layer least-squares memory objective for a batch of n keys/values, and its solution via the normal equation (the same starting point ROME used, but now explicitly for u≫1 simultaneous associations rather than one).
- **equation_verbatim**: W0 ≜ argmin_Ŵ Σ_{i=1}^{n} ||Ŵ k_i − m_i||^2                                          (7)
W0 K0 K0^T = M0 K0^T                                                                    (8)
- **symbols**: W0 ≜ W^l_out (the pretrained MLP fan-out weight matrix of the target layer); k_i ≜ k^l_i (input key encoding the subject for memory i); m_i ≜ m^l_i (memorized value/property for memory i); n = number of pre-existing memories; K0 = [k1|k2|···|kn], M0 = [m1|m2|···|mn] = the stacked key/memory matrices.
- **assumptions**: The layer is modeled exactly as a linear associative memory (Kohonen 1972; Anderson 1972), same framing as ROME, now explicitly for a batch of size n rather than n=1.
- **derivation_steps**: Source states Eq. 7 optimizes 'by solving the normal equation (Strang, 1993, Chapter 4)' directly to Eq. 8 — no intermediate algebra shown for this step (it is the standard least-squares normal-equation result, cited rather than re-derived).
- **worked_numbers**: none
- **source**: meng-memit-2023.pdf
- **locator**: §4.2 'Batch Update for a Single Linear Associative Memory,' p.4 (Eqs. 7-8)

### 7. MEMIT — batched multi-association update (closed form Δ)
- **statement**: MEMIT derives the update Δ that must be added to W0 to satisfy an EXPANDED set of associations (n old + u new) simultaneously with minimal squared error, following the same normal-equation route as ROME's Appendix A but for a batch of new associations rather than a rank-one constraint — yielding a closed form involving only a residual R and a covariance-like statistic, without ever needing the (inaccessible) original K0, M0 individually.
- **equation_verbatim**: W1 ≜ argmin_Ŵ [ Σ_{i=1}^{n} ||Ŵ k_i − m_i||^2 + Σ_{i=n+1}^{n+u} ||Ŵ k_i − m_i||^2 ]                                    (9)
W1 [K0 K1][K0 K1]^T = [M0 M1][K0 K1]^T                                                                                    (10)
(W0+∆)(K0K0^T + K1K1^T) = M0K0^T + M1K1^T                                                                                 (11)
W0K0K0^T + W0K1K1^T + ∆K0K0^T + ∆K1K1^T = M0K0^T + M1K1^T                                                                 (12)
[subtracting Eq.8 from Eq.12:]   ∆(K0K0^T + K1K1^T) = M1K1^T − W0K1K1^T                                                   (13)
∆ = R K1^T (C0 + K1K1^T)^{-1}                                                                                             (14)
C0 = λ · E_k[k k^T]                                                                                                       (15)
- **symbols**: W1 = the new post-edit MLP weight matrix; K1 = [k_{n+1}|···|k_{n+u}], M1 = [m_{n+1}|···|m_{n+u}] = the new keys/values (the u new memories being inserted); ∆ = W1−W0, the sought update; C0 ≜ K0K0^T = a constant proportional to the uncentered covariance of the PRE-EXISTING keys; R ≜ M1 − W0K1 = the residual error of the new associations evaluated on the OLD weights W0; λ = a hyperparameter balancing weighting of new vs. old associations; E_k[kk^T] = the empirically estimated uncentered second-moment/covariance statistic of keys.
- **assumptions**: Pretraining is opaque — K0 and M0 (the actual pre-existing keys/values) are never directly available, so the derivation is engineered so the final formula (Eq. 14) needs only the AGGREGATE statistic C0, not the individual K0/M0. The set of previously memorized keys is modeled as a random sample of inputs, justifying estimating C0 = λ·E[kk^T] from an external corpus sample (as ROME did) rather than from the true pretraining keys.
- **derivation_steps**: Fully shown: (1) write the expanded batch objective over both old and new associations (Eq. 9); (2) apply the normal equation in block form over the concatenated key/value matrices (Eq. 10); (3) expand the block product (Eq. 11-12); (4) subtract the single-layer normal equation for W0 (Eq. 8) from Eq. 12 — 'most terms cancel' analogous to ROME's Appendix A — isolating ∆ (Eq. 13); (5) define C0 ≜ K0K0^T and R ≜ M1−W0K1 to write Eq. 13 compactly, then solve for ∆ (Eq. 14); (6) note that computing Eq. 14 needs only the aggregate statistic C0, which is then modeled/estimated as λ·E[kk^T] (Eq. 15) since K0,M0 are inaccessible.
- **worked_numbers**: typical value λ = 1.5 × 10^4.
- **source**: meng-memit-2023.pdf
- **locator**: §4.2, p.4-5 (Eqs. 9-15)

### 8. MEMIT — spreading the residual across multiple critical layers
- **statement**: MEMIT computes one target vector z_i per edit at a single 'end' layer L via gradient descent (analogous to ROME's v* optimization but at the residual-stream level, not just the MLP output), then distributes the implied change evenly across every critical MLP layer l ∈ R (rather than writing the whole change into one layer, as ROME does), recomputing keys and residual weighting at each layer in ascending order.
- **equation_verbatim**: z_i = h^L_i + argmin_{δ_i} (1/P) Σ_{j=1}^{P} [ −log P_{G(h^L_i += δ_i)}[o_i | x_j ⊕ p(s_i,r_i)] ]                          (16)
setting Ŵ^l_out := W^l_out + ∆^l for all l ∈ R optimizes  min_{{∆^l}} Σ_i ||z_i − ĥ^L_i||^2                                  (17)
where ĥ^L_i = h^0_i + Σ_{l=1}^{L} a^l_i + Σ_{l=1}^{L} Ŵ^l_out σ(W^l_in γ(h^{l−1}_i))                                          (18)
k^l_i = (1/P) Σ_{j=1}^{P} k(x_j + s_i),  where  k(x) = σ(W^l_in γ(h^{l−1}_i(x)))                                             (19)
m^l_i = W_out k^l_i + r^l_i  where r^l_i is the residual given by  (z_i − h^L_i)/(L − l + 1)                                  (20)
- **symbols**: L ≜ max(R), the last (deepest) layer of the critical mediating range R; δ_i = the perturbation applied to the residual stream at layer L to be optimized; z_i = h^L_i + δ_i, the target hidden state encoding the new fact; P = number of random prefix texts used (analogous to N/prefixes in ROME); x_j⊕p(s_i,r_i) = a prefix concatenated with the templated relation prompt; ĥ^L_i = the model's hidden state as a function of the (still-being-optimized) per-layer updates {∆^l}; r^l_i = the fraction of the remaining top-level residual (z_i−h^L_i) assigned to layer l, divided evenly over the L−l+1 remaining layers from l to L.
- **assumptions**: Edits to any layer influence all downstream layers' activations, so ∆^l must be computed iteratively in ascending layer order, re-collecting activations after each layer's update (rather than solving all layers simultaneously). The residual is 'spread out evenly' across remaining layers — an explicit, stated design choice (motivated by the observation, cited to Zhu et al. 2020, that robustness improves when parameter-change magnitude is minimized), not derived from an optimality argument.
- **derivation_steps**: Eq. 16 (z_i) is stated as the definition of the gradient-descent objective, directly analogous to (but at the residual-stream level rather than MLP-output level of) ROME's v* objective — no further derivation given. Eq. 17-18 state the overall multi-layer objective; the actual per-layer solve at each l reduces to the single-layer closed form of Eq. 14 (previous item) applied with K^l, M^l built from Eq. 19-20 — this connection is stated in prose ('To compute each individual ∆^l, we need the corresponding keys K^l... and memories M^l... to insert using Eqn. 14') rather than re-derived algebraically.
- **worked_numbers**: For GPT-J, the identified critical MLP layer range is R = {3,4,5,6,7,8} (so L=8); this range was chosen because 'this gap [between single-state effect and MLP-severed effect] diminishes after layer 8' in the causal-tracing sweep (Fig. 3).
- **source**: meng-memit-2023.pdf
- **locator**: §4.3 'Updating Multiple Layers,' p.5 (Eqs. 16-20); Algorithm 1, p.5

### 9. CAA — Mean Difference (MD) steering-vector construction
- **statement**: Contrastive Activation Addition computes its steering vector as the empirical average, over a dataset of matched positive/negative prompt-completion triples, of the difference in residual-stream activation at the answer-letter token position between the positive and negative completions of the same underlying question — a direct instance of the difference-in-means construction applied to paired multiple-choice prompts.
- **equation_verbatim**: v_MD = (1/|D|) Σ_{p,c_p,c_n∈D} [ a_L(p,c_p) − a_L(p,c_n) ]                                                             (1)
- **symbols**: D = a dataset of (prompt p, positive completion c_p, negative completion c_n) triples; a_L(p,c) = the residual-stream activation vector at layer L, at the position of the answer letter, when the model processes prompt p followed by completion c; v_MD = the resulting Mean Difference steering vector for layer L; |D| = number of triples.
- **assumptions**: Prompt pairs are multiple-choice questions with letter-only completions ('A'/'B') differing solely in which letter corresponds to the target vs. opposite behavior — so the activation difference is attributed to the choice of behavior rather than to unrelated lexical/content differences. The construction is stated to be justified empirically ('has been shown to produce steering vectors similar to other techniques like PCA,' citing Tigges et al. 2023) rather than proven optimal in this paper.
- **derivation_steps**: source states the formula directly (Eq. 1) with no derivation from a deeper statistical principle — it is presented as 'this method of extracting the difference vector is called Mean Difference (MD).'
- **worked_numbers**: Steering applied at layer 13 of Llama 2 (7B/13B) Chat in the reported experiments; Table 3 (13B model) gives concrete multiplier-sweep numbers for average token probability on the target behavior across multipliers {−1, 0, +1} crossed with system-prompt condition {None, Positive, Negative} — e.g. AI Coordination: 0.20→0.22→0.39 (None), 0.28→0.34→0.54 (Positive), 0.21→0.22→0.43 (Negative); Refusal: 0.56→0.78→0.86 (None). These are the concrete worked numbers for how steering strength interacts with prompting.
- **source**: rimsky-caa-2024.pdf

### 11. ActAdd — steering-vector construction and injection algorithm
- **statement**: ActAdd's Algorithm 1 formalizes activation addition exactly as: form a contrast pair of prompts, take the difference of their layer-l activations, rescale by an injection coefficient c, and add this vector to the residual stream at layer l, position a, of the user's prompt before continuing the forward pass.
- **equation_verbatim**: Algorithm 1 ActAdd, optimization-free activation addition
Input: (p+, p−) = steering prompt pair, tokenized; p* = user prompt; l = target layer; c = injection coefficient; a = sequence position to align h_A and h_{p*}; M = pretrained language model
Output: S = steered output
(p'+, p'−) ← pad right same token len(p+, p−)
h^l_+ ← M.forward(p'+).activations[l]
h^l_− ← M.forward(p'−).activations[l]
h^l_A ← h^l_+ − h^l_−
h^l ← M.forward(p*).activations[l]
S ← M.continue_forward(c·h^l_A + h^l @ a)
- **symbols**: p+, p− = the contrastive steering prompts (e.g. 'Love' vs. 'Hate'); p* = the user's prompt to be steered; l = the target layer for injection; c = the injection coefficient (scalar multiplier on the steering vector — this IS the object of the coefficient-tradeoff question); a = the sequence position at which the steering vector h^l_A is aligned with / added to the residual stream of h^l (the user-prompt activations); h^l_+, h^l_− = activations of the contrast prompts at layer l; h^l_A = h^l_+ − h^l_− = the steering vector (difference of activations); h^l = residual-stream activations of the user prompt at layer l; M.continue_forward = continuing the forward pass with the modified activation.
- **assumptions**: The contrast prompts are padded to equal token length before the forward pass ('pad right same token len') so that h^l_+ and h^l_− are directly comparable/subtractable at matched positions. Middle layers are empirically found most effective for injection (citing Subramani et al. 2022; Mini et al. 2023) — not derived, an empirical finding reused from prior work.
- **derivation_steps**: source states the algorithm directly as a design (Algorithm 1); no derivation of WHY this construction works beyond the intuitive description ('the difference hl+ − hl− is a new activation vector which (intuitively) captures the difference between a prompt with the target property, and a prompt without it').
- **worked_numbers**: c represents intervention strength; footnote states: 'It's typical for the intervention strength c to have a magnitude less than 15.' Grid search in experiments used c ∈ [3,20] and l ∈ [6,24] (Appendix). Worked example: p+='weddings', p−='' (empty), l=16, c=1 for the running 'wedding topic' example.
- **source**: turner-activation-addition-2023.pdf
- **locator**: §3 'How Activation Addition Works,' Algorithm 1, p.4; footnote 2, p.5; Appendix, 'ActAdd hyperparameters (l,c),' p.11

### 13. RepE — stimulus-based reading-vector construction (concepts and functions)
- **statement**: Representation Engineering constructs 'reading vectors' by collecting last-token activations on either single stimuli (for concepts, e.g. honesty) or paired experimental/reference completions truncated at varying lengths (for functions), then applying an unsupervised linear model (primarily PCA on the set of PAIRWISE DIFFERENCES of activations) to extract a single direction.
- **equation_verbatim**: A_c = { Rep(M, T_c(s_i))[−1] | s_i ∈ S }                                                                              (1)
A^{±}_f = { Rep(M, T_f(q_i, a^k_i))[−1] | (q_i,a_i) ∈ S, for 0 < k ≤ |a_i| }                                            (2)
[PCA inputs, stated in prose, no eq. number:]  inputs to PCA are {A_c(i) − A_c(j)} for concepts and {(−1)^i (A^{(i)+}_f − A^{(i)−}_f)} for functions
- **symbols**: M = decoder model; Rep(M, x) = function returning representations at all token positions for input x; [−1] = the last token position; c = a target concept; f = a target function; T_c, T_f = templating functions turning a stimulus (or query-answer pair) into a full prompt; S = the stimulus set; s_i = an individual stimulus (for a concept); (q_i, a_i) = an instruction-response pair (for a function); a^k_i = the response a_i truncated after token k; A_c, A^±_f = the resulting sets of collected activation vectors; v = the extracted 'reading vector' (first principal component of the PCA on differences).
- **assumptions**: Effectiveness of PCA-on-differences is stated to require that 'the stimuli in each pair share similarities except for the target concept or function' — i.e. paired/matched stimulus construction is assumed, not incidental. Predictions are made via the dot product Rep(M,x)^T v (stated in prose, not tagged as an equation).
- **derivation_steps**: source states without derivation — this is a described procedure ('Step 2: Collecting Neural Activity' and 'Step 3: Constructing a Linear Model'), not an algebraic derivation of why PCA-of-differences or difference-of-means is optimal.

### 14. RepE — three formal control (editing) operators
- **statement**: Representation Engineering names and formalizes three distinct ways a 'control element' (steering vector) v can be applied to modify a representation R into R′: additive shift, sign-conditional (piecewise) amplification, and orthogonal projection/erasure. The projection operator is algebraically identical in form to what Arditi et al. later call 'directional ablation.'
- **equation_verbatim**: 1. Linear Combination: R′ = R ± v
2. Piece-wise Operation: R′ = R + sign(R^T v) v
3. Projection: R′ = R − (R^T v / ||v||^2) v
- **symbols**: R = the original representation (activation vector) being controlled; R′ = the transformed representation; v = the control element (e.g. a reading/contrast vector); sign(·) = the sign function applied to the scalar projection R^Tv; ||v||^2 = squared Euclidean norm of v.
- **assumptions**: 'The control elements v can be scaled by coefficients, depending on the strength of the desired effect, which we omit for simplicity' — i.e. the paper explicitly elides the coefficient/strength parameter from this formal statement of the three operators, folding the coefficient question into implementation detail rather than theory.
- **derivation_steps**: source states without derivation — these are DEFINED operators (design choices for different control objectives: 'stimulation or suppression' for #1, 'conditional effects' for #2, 'eliminating' a component for #3), not derived from an optimality criterion.
- **worked_numbers**: in application (§ concrete experiments, not part of this formal definition): e.g. Contrast Vector applied with coefficient 0.25 at layers range(8,32,3) for the 7B model (same coefficient/layers for 13B).
- **source**: zou-representation-engineering-2023.pdf
- **locator**: §3.2 'Representation Control,' 'Choices for Operators,' p.11; coefficient example at 'Contrast Vector' implementation notes, p. (appendix, ~2839)

### 15. RepE — LoRRA (contrast-vector-supervised low-rank adaptation) training loop
- **statement**: As an alternative to directly adding a steering vector at inference time, RepE proposes learning a low-rank adapter (LoRRA) whose loss pulls the adapted model's representation at target layers toward a 'target representation' constructed by adding a scaled contrast vector (and/or a scaled precomputed reading vector) to the base representation.
- **equation_verbatim**: Algorithm 1 (excerpted): 
v^c_l = R(M,l,x^+_i) − R(M,l,x^−_i)                       [Contrast Vectors]
r^p_l = R(M^{LoRA}, l, x_i)                                [Current representations]
r^t_l = R(M,l,x_i) + α v^c_l + β v^r_l                     [Target representations]
m = [0,...,1]                                              [Masking out positions before the response]
L = L + ||m(r^p_l − r^t_l)||^2
- **symbols**: M = original frozen model; M^{LoRA} = model with LoRA adapters attached; L_e, L_t = layers to edit / layers to target respectively; T^0, T^+, T^− = base/positive/negative contrastive prompt templates; x_i, x^+_i, x^−_i = the base/experimental/reference prompt instantiations for example i; α, β = scalar coefficients weighting the contrast-vector term and the (optional) precomputed reading-vector term v^r_l respectively; m = a binary mask zeroing out loss contribution from token positions before the model's response begins; L = the accumulated squared-error training loss.
- **assumptions**: One of α, β can be zero (e.g. reported experiment setting uses α=5, β=0, i.e. pure contrast-vector supervision with no separately-precomputed reading vector); T+/T− are sampled uniformly per training example from a set of m contrastive template triples.
- **derivation_steps**: source states without derivation — this is a training procedure (an algorithm), and its loss (squared distance between current and target representation) is a direct design choice paralleling the same 'move representation toward a target' idea used algebraically in ROME/MEMIT's k*/v* and z_i steps, but here realized via gradient descent on adapter weights rather than a closed-form weight edit.
- **worked_numbers**: α=5, β=0 for the LoRRA parameters reported in one setting.
- **source**: zou-representation-engineering-2023.pdf
- **locator**: §3.2, Algorithm 1 'Low-Rank Representation Adaptation (LoRRA) with Contrast Vector Loss,' p.11

### 16. Arditi — difference-in-means direction, activation addition, and directional ablation
- **statement**: Arditi et al. construct a 'refusal direction' as the difference-in-means of post-instruction-token activations between harmful and harmless prompt sets (citing this technique to Belrose 2023), then define two symmetric interventions: adding the direction (activation addition, to induce the behavior) and orthogonally projecting it out (directional ablation, to erase/bypass the behavior).
- **equation_verbatim**: µ_i^{(l)} = (1/|D_harmful^{train}|) Σ_{t∈D_harmful^{train}} x_i^{(l)}(t),   ν_i^{(l)} = (1/|D_harmless^{train}|) Σ_{t∈D_harmless^{train}} x_i^{(l)}(t)                                                                                          (2)
[difference-in-means vector, stated in prose, not separately tagged:]  r_i^{(l)} = µ_i^{(l)} − ν_i^{(l)}
x'^{(l)} ← x^{(l)} + r^{(l)}                                                                                             (3)
x' ← x − r̂ r̂^T x                                                                                                       (4)
- **symbols**: µ_i^{(l)}, ν_i^{(l)} = mean activation at layer l, post-instruction token position i, over harmful / harmless training prompts respectively; D_harmful^{train}, D_harmless^{train} = the training splits of harmful and harmless prompt sets; r_i^{(l)} = the difference-in-means vector at layer l, position i; x^{(l)} = an activation being intervened on (Eq. 3, activation addition); r̂ = the unit-norm version of the selected difference-in-means vector (r̂ = r/||r||); Eq. 4 applies to EVERY residual-stream activation x ∈ R^{d_model}, at every layer l and token position i, not just at one layer as in Eq. 3.
- **assumptions**: For activation addition (Eq. 3), the direction r^{(l)} is added only at ONE chosen layer l*, across all token positions. For directional ablation (Eq. 4), the SAME direction r̂ is subtracted at EVERY layer and every token position — 'this effectively prevents the model from ever representing this direction in its residual stream.' The difference-in-means technique itself is credited to Belrose (2023), not derived here.
- **derivation_steps**: source states without derivation for both the difference-in-means construction and the two intervention formulas — these are presented as direct definitions/techniques, with the paper's own contribution being their SELECTION procedure (below) and empirical validation, not a derivation of optimality.
- **worked_numbers**: none in this construction section (selection thresholds given in the next item)
- **source**: arditi-refusal-direction-2024.pdf

### 17. Arditi — direction-selection algorithm as an implicit coherence/efficacy tradeoff criterion
- **statement**: Because many candidate difference-in-means directions exist (one per layer × token position), the paper selects the single best one using three empirical scores, including a KL-divergence-based threshold that operationalizes 'does not damage coherence/behavior on unrelated (harmless) inputs' — this is the closest any of the surveyed papers comes to a formal proxy for the coefficient/injection-strength tradeoff, though it selects a DIRECTION/LAYER rather than a continuous coefficient.
- **equation_verbatim**: source states without a single consolidated equation; the three scores and thresholds are: bypass_score = average refusal metric on D_harmful^{val} under directional ablation of r_i^{(l)}; induce_score = average refusal metric on D_harmless^{val} under activation addition of r_i^{(l)}; kl_score = average KL divergence between (with vs. without directional ablation of r_i^{(l)}) output distributions at the last token, run on D_harmless^{val}. Selection rule: choose r_{i*}^{(l*)} minimizing bypass_score subject to: induce_score > 0; kl_score < 0.1; l < 0.8L.
- **symbols**: D_harmful^{val}, D_harmless^{val} = validation splits; bypass_score, induce_score, kl_score = the three selection metrics defined above; L = total number of layers; l < 0.8L restricts candidate layers to the first 80% of the network depth (stated rationale: avoids directions too close to unembedding directions, e.g. directions writing directly to the 'I' or 'As' token logits).
- **assumptions**: kl_score is computed only on HARMLESS prompts — i.e. the coherence criterion is specifically 'does ablating this direction change behavior on inputs where it SHOULDN'T matter,' not a general fluency/perplexity measure. The 0.1 KL threshold and 0.8L layer cutoff are stated as chosen conditions, not derived from a formal bound.
- **derivation_steps**: source states without derivation — the three scores and the threshold values (0.1, 0.8L) are presented as the selection procedure with brief post-hoc rationale for each filter, not derived from an optimization.
- **worked_numbers**: kl_score < 0.1 (threshold); l < 0.8L (layer-depth threshold, L = total layer count).
- **source**: arditi-refusal-direction-2024.pdf
- **locator**: Appendix C.1 'Direction selection algorithm,' p.20

### 18. Cohen et al. — formal ripple-effect taxonomy (six evaluation criteria + severity)
- **statement**: RippleEdits formally defines an edit's ripple effect as the set of knowledge-graph triplets logically implied to change by a single factual edit, and decomposes evaluation of whether a model correctly propagates an edit into six precisely-specified relational criteria (Logical Generalization, Compositionality I, Compositionality II, Subject Aliasing, Preservation, Relation Specificity), plus a scalar 'severity' measure.
- **equation_verbatim**: [Setup, stated formally in prose with inline notation, not display-tagged equations:]
Knowledge graph: K := {(e_i, r_i, o_i)}_{i=1}^{N}
Edit request: δ : (e, r, o) → (e, r, o')
Ripple effect: R(δ) = the set of triplets that the model implicitly needs to inject, modify, or delete from K to reflect the world state after the edit
Severity: |R(δ)|

Criteria (each formalized similarly):
1. Logical Generalization (LG): symmetric/inverse relation constraints, e.g. (e, Sibling, o) true ⟹ (o, Sibling, e) true, and vice versa; after edit, both must update together.
2. Compositionality I (CI): given facts (o,r',z) and (o*,r',z*) of the same relation about o and o*, and r'' = r∘r' the composed relation, after edit δ we expect (e,r'',z) → (e,r'',z*).
3. Compositionality II (CII): given (e',r',e) a fact about e' with e as object, and r''=r'∘r the composed relation, after edit δ we expect (e',r'',o) → (e',r'',o*) for the subject e'.
4. Subject Aliasing (SA): for e' an alias of e, editing (e,r,o)→(e,r,o*) should also induce (e',r,o)→(e',r,o*).
5. Preservation (PV): for a one-to-many relation r, adding object o* should not affect other existing (e,r,o') for o'≠o*.
6. Relation Specificity (RS): facts about e under OTHER relations, whose objects are not causally influenced by o, should remain unaffected by the edit.
- **symbols**: K = the model's implicit knowledge graph of N factual triplets (entity e, relation r, object o); δ = the edit request; R(δ) = the set of implied downstream triplet changes ('ripple effect'); |R(δ)| = 'severity' of the edit (number of implied facts affected); r'' = r∘r' or r'∘r = a COMPOSED relation combining two base relations (e.g. Sibling ∘ Profession = 'profession of sibling'); e, o, e', o', o* = specific entities/objects in the various criteria.
- **assumptions**: Evaluation is restricted to facts within a 2-HOP distance from the subject/object of the edit ('given that ripple effects can potentially span a large number of implied edits, we focus on evaluating modified facts that are within a 2-hop distance'). Popular/frequently-trained entities are assumed to induce higher-severity ripple effects than rare entities ('editing popular entities... is likely to introduce more changes').
- **derivation_steps**: these are DEFINITIONS (a formal evaluation taxonomy), not a derivation from a deeper principle — the paper states each criterion as a formal specification directly, illustrated with a worked example (editing Prince's siblings) for each of the six.
- **worked_numbers**: none in the definitional section (concrete measured pass rates for each criterion are given in the next item)
- **source**: cohen-ripple-effects-2023.pdf
- **locator**: §3 'Ripple Effects of Factual Edits,' §3.1 'Evaluation Criteria,' p.2-3

### 20. Gupta et al. — gradual vs. catastrophic forgetting, and the L2-distance mechanism
- **statement**: The paper formally distinguishes two DISTINCT phases of degradation under sequential single-fact editing: (1) 'gradual forgetting' — a slow, monotonically increasing rate of previously-edited-fact loss and downstream-task degradation as more edits accumulate, and (2) 'catastrophic forgetting' — an abrupt INFLECTION POINT after which the model suddenly forgets a large fraction of edited facts and loses general downstream-task ability entirely. It ties this mechanistically to the normalized L2 distance between the edited layer's weights and its ORIGINAL (pre-edit) weights, which grows gradually and then SPIKES at the same point catastrophic forgetting begins — because the edited layer becomes 'incompatible' with the rest of the (unedited) transformer, which was trained expecting inputs/outputs consistent with the original weights.
- **equation_verbatim**: source states without a display equation — the L2-distance metric is defined in prose (footnote 5): 'We first take the L2 norm between original and post-edit weights of the layer being edited, and then normalize it by number of neurons in the layer.'
'Catastrophic forgetting is defined as the sudden loss of ability of a model to perform a prior task when it is further trained to perform a new task.' (citing Goodfellow et al. 2013; Kirkpatrick et al. 2017 for the general ML definition, applied here to sequential model editing)
'We define the first region where the model progressively loses its ability to do prior tasks... as gradual forgetting.'
'Disabling edits' are defined operationally: a SINGLE edit that, applied as the FIRST edit to an otherwise-unedited model, already leaves the model completely disabled, with a normalized weight-distance comparable to what is seen at the catastrophic-forgetting spike under sequential editing.
- **symbols**: normalized L2 distance = ||W_edited − W_original||_2 / (number of neurons in the layer); 'gradual forgetting' = the region prior to the inflection point where fact-recall and downstream accuracy decline slowly and monotonically with number of edits; 'catastrophic forgetting' = the region after the inflection point, characterized by a sudden large increase in forgotten facts and loss of downstream ability; 'disabling edits' = specific facts that ROME cannot successfully edit without individually crippling the model, even as a first/only edit.
- **assumptions**: The mechanistic account ('source of forgetting,' §3.4) is an ARGUMENT, not a proof: transformers are described as 'a machine made from very specific parts working together,' where each layer must be 'compatible' with what adjacent layers expect; continuously editing one layer while holding the rest fixed is argued to eventually break this compatibility once the edited layer diverges enough from its original form. This is offered as an explanation for WHY the L2-distance spike coincides with the forgetting inflection point, not derived from a formal bound. Localization of facts to specific MLP layers is itself an assumption inherited from ROME, 'backed by causal tracing experiments (Meng et al., 2022a).'
- **derivation_steps**: source states without derivation — this is an empirically-grounded mechanistic narrative supported by the measured coincidence of (a) the L2-distance spike, (b) the forgetting-rate spike, and (c) the downstream-task-collapse point, plus the disabling-edits experiment (isolating a SINGLE edit reproduces the same large L2 distance, ruling out 'accumulation over many edits' as the necessary cause and pointing instead to a per-fact difficulty/incompatibility explanation).
- **worked_numbers**: Table 2: average normalized L2 distance between edited layer and original weights — DISABLING EDITS: 3.339×10^-4; NORMAL EDITS: 8.156×10^-7 (i.e. disabling edits show a distance roughly THREE ORDERS OF MAGNITUDE larger than normal edits, stated explicitly in prose: 'disabling edits have three orders of magnitude larger distance than non-disabling edits'). For MEMIT (batched, one-fact-at-a-time in this experiment), catastrophic forgetting onset is 'approximately 1400 edits'; MEMIT forgets 'almost three times fewer facts' than ROME by the same point. ROME's inflection point 'can come as early as 100 edits, or as late as 1000 edits' depending on the sample.
