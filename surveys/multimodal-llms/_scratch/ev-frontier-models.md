## Q1 — New open-weight multimodal/vision-language model releases, 2026-05 through 2026-08

Note on scope: several widely-cited open VLMs (Qwen3-VL, InternVL3.5) that keep surfacing in "2026 landscape" round-ups were actually released **before** the survey's 2026-06-28 freeze (Qwen3-VL: Sep–Nov 2025, arXiv:2511.21631 technical report Nov 27 2025; InternVL3.5: Aug 26 2025, arXiv:2508.18265). They are NOT new for this sweep and are listed only as negative findings / to avoid double-counting. The genuinely new-in-window items follow.

- **Kimi K3 (Moonshot AI)** — launched July 16, 2026; full open weights on Hugging Face July 27, 2026 — 2.8T total parameters, MoE with 896 experts / 16 activated per token, ~104B active parameters (one secondary source said "~50B active," HF-card-sourced figure of 104B active is the more specific/recent one — flagged as a minor discrepancy across secondary sources, not resolved against the primary HF card page itself since it wasn't directly fetched) — vision encoder **MoonViT-V2** (401M params, native multimodal input) — context window **1,048,576 tokens (1M)** — licence: "Kimi K3 License," described as a modified-MIT license permitting commercial use — *source:* https://huggingface.co/moonshotai/Kimi-K3 (per secondary reporting; card itself not fetched) and https://medium.com/data-science-in-your-pocket/kimi-k3-weights-released-on-huggingface-8dcd58e29b55 (dated July 2026) and https://venturebeat.com/technology/chinas-moonshot-ai-releases-kimi-k3-the-largest-open-source-model-ever-rivaling-top-u-s-systems — *quality:* silver (secondary tech reporting citing the HF card; card not independently opened). Connector architecture and native-resolution handling for MoonViT-V2: UNSOURCED — do not cite (not found in search snippets).

- **MOSS-VL-Realtime (OpenMOSS / SII / Fudan / Mosi)** — open-sourced ~July 2026 — 11B parameters — architecture: **cross-attention-based** vision-language design (decouples visual encoding from language reasoning), with a novel **XRoPE** (Cross-attention Rotary Position Embedding) mapping text tokens and video patches into a unified (t, h, w) 3D coordinate space, timestamp-aware frame encoding for continuous video streams — context window **256K tokens** — licence **Apache-2.0** — designed for real-time streaming video Q&A (can stay silent / revise answers as new frames arrive) — *source:* https://huggingface.co/OpenMOSS-Team/MOSS-VL-Realtime and https://x.com/MosiAI_Official/status/2076989390191202577 and https://github.com/OpenMOSS/MOSS-VL — *quality:* silver (HF org page + official announcement thread; not independently fetched as a formal model card). Parameter counts for vision tower vs. LLM decoder individually, and precise release date/day: UNSOURCED — do not cite.

- **LFM2.5-VL-3B (Liquid AI)** — released August 13, 2026 — 3.1B parameters — vision encoder: **SigLIP2 400M NaFlex** (Google), paired with Liquid AI's own **LFM2.5-2.6B** text backbone (native resolution / "NaFlex" flexible-aspect-ratio handling implied by the SigLIP2-NaFlex choice, but the exact native-resolution mechanism was not itself detailed in the snippet) — context length **32,768 tokens** — pre-training corpus ~34T tokens — licence: **LFM Open License v1.0**, described as "Apache-2.0-based with one change" (the exact change was cut off in the snippet and not verified) — targeted at on-device / edge use: screen reading, object grounding, document/chart parsing, tool calling — *source:* https://www.liquid.ai/blog/lfm2-5-vl-3b (vendor blog / model announcement) and https://huggingface.co/LiquidAI/LFM2.5-VL-3B and https://www.marktechpost.com/2026/08/13/liquid-ai-lfm2-5-vl-3b-on-device-vision-language-model/ — *quality:* silver-to-gold (vendor blog is close to a model-card source but was not itself fetched; MarkTechPost corroborates date and specs). Connector/projector type between SigLIP2 and LFM2.5 text backbone: UNSOURCED — do not cite.

- **GLM-4.6V (Z.ai / Zhipu)** — NOT confirmed to be in the 2026-05..08 window. The only dated coverage found (MarkTechPost URL path `/2025/12/09/...`) implies a **Dec 2025** release, i.e. before the survey freeze — likely already covered by the frozen survey, or a borderline case. Specs found (for reference, not claimed as "new"): two sizes, GLM-4.6V (106B) and GLM-4.6V-Flash (9B); vision encoder **AIMv2-Huge ViT** + MLP projector (merge_size default 2); context window **128K tokens**; licence **MIT**. *source:* https://www.marktechpost.com/2025/12/09/zhipu-ai-releases-glm-4-6v-a-128k-context-vision-language-model-with-native-tool-calling/ and https://huggingface.co/zai-org/GLM-4.6V — *quality:* silver — **flag: release-date ambiguous, do not present as "new since June 2026" without further verification.**

## Q2 — Frontier closed models, 2026-05 through 2026-08 (GPT/Gemini/Claude families)

Headline finding, sourced to official docs: **neither the GPT-5.6 family nor Gemini 3.7 Flash documents true native any-to-any (multi-modality-out) generation as of Aug 2026.** Both remain text-output models with rich multimodal *input*; image/video/audio generation is exposed as separate tool-orchestration, not a documented native output modality of the core model.

- **GPT-5.6 (Sol / Terra / Luna variants, OpenAI)** — officially released late June 2026 (limited preview to trusted partners/developers) — documented per OpenAI's own API model pages: inputs = text + image; **native output = text and tool calls only**; audio/video are not supported as direct inputs/outputs of the core model. Image generation is exposed via a separate `image_generation` tool that calls the standalone **gpt-image-2** model; video generation (e.g. via Sora 2) is agent-level tool orchestration, not native model output — *source:* https://developers.openai.com/api/docs/models/gpt-5.6-sol and https://developers.openai.com/api/docs/models/gpt-5.6-terra (official API docs) — *quality:* gold (primary vendor docs) for the "text + tool-calls only" output claim; secondary summarization via WebSearch snippet, not independently fetched page-by-page, so treat as silver-leaning-gold pending direct fetch verification.
  - GPT-5.6 Sol reported throughput **750 tokens/second on Cerebras** hardware — *source:* https://thewincentral.com/openai-gpt-5-6-sol-cerebras-750-tokens-per-second/ — *quality:* bronze/silver (tech-press, vendor-partnership announcement; not an OpenAI-published number in a system card).
  - **gpt-image-2** (companion image-gen model): officially released **April 21, 2026** — before the survey's 2026-06-28 freeze, so background context only, not new-in-window. 4K resolution output, "near-perfect text rendering," reasoning-powered generation, replaces DALL-E 3 / GPT Image 1.5 — *source:* https://www.befreed.ai/blog/gpt-image-2-guide-2026 — *quality:* bronze (vendor-adjacent blog, not the OpenAI system card itself; not independently verified).
  - A GPT-5.5 system-card-style document was found only as "Addendum to GPT-4o System Card: Native image generation" (OpenAI, **March 25, 2025** — well before window; not relevant to this sweep except as background). No GPT-5.6 or GPT-5.5-specific system-card PDF was located in search snippets — **flag: could not confirm existence/contents of a formal GPT-5.6 system card via search; only API doc pages and secondary press were found.**

- **Gemini 3.7 Flash (Google DeepMind)** — released **August 13, 2026** ("three weeks after Gemini 3.6 Flash") — knowledge cutoff March 2026 — documented (official model card, DeepMind): inputs = text, image, video, audio, PDF; **output = text only**; explicitly "does not natively generate images or audio" — *source:* https://deepmind.google/models/model-cards/gemini-3-7-flash/ and https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-3-7-flash/ and https://www.marktechpost.com/2026/08/13/google-ai-just-released-gemini-3-7-flash/ — *quality:* gold (official DeepMind model card confirmed via search snippet; page itself not independently fetched for 3.7 — the 3.1-Flash-Audio fetch below is the directly-verified fetch for this window).

- **Gemini 3.1 Flash Audio / Flash Live (Google DeepMind)** — published **March 26, 2026, updated April 2026** — this is technically just before the survey freeze window boundary but is the most recent *documented* real-time streaming-audio/video model card found, and remains the operative spec as of Aug 2026 (no evidence of a newer streaming-audio card superseding it inside the window). **Directly fetched and verified** (WebFetch, 2026-08-15) from https://deepmind.google/models/model-cards/gemini-3-1-flash-audio/ :

  - Output capacity: Flash Live = **64K token output**; Flash TTS = **32K token output**.

This is the clean documented-vs-marketing gap the survey should flag: the capability claim ("real-time voice and video interactions") is present in the primary model card, but the *quantitative* substantiation is not — it defers to the (also not fetched here) underlying Gemini 3 Pro model card.

## Q3 — Architectural direction: is CLIP-style-encoder + MLP-projector + LLM still dominant?

**Honest top-line finding: mostly NO CHANGE in the dominant paradigm since the 2026-06-28 freeze, but the pre-existing challenger trend (native-resolution encoders, and separately encoder-free/pixel-direct designs) continued to mature and got at least one notable "graduation to a mid-sized production release" data point (Gemma 4 12B). Vision-tower MoE remains a research-stage idea, not a production pattern.** Three sub-trends, each with its own evidence and honesty caveat:

1. **Native/dynamic-resolution vision encoders — already the established trend pre-freeze, continuing, not a post-freeze shift.** "Native-resolution vision encoders have become a standard architectural trend in the vision-language model space leading up to and beyond June 2026," per a search-engine synthesis citing Qwen2.5-VL, Seed-VL-1.5, and Kimi-VL as pioneers (all pre-2026-06-28). The CLIP+MLP+LLM stack itself has already been evolving toward NaViT-style native-resolution encoders for >1 year — this is not a new development in the sweep window, it is a continuation. New-in-window data point: **Kwai Keye-VL-2.0-30B-A3B**, released **May 25, 2026** (arXiv:2606.10651, technical report June 2026) — an open-source **MoE** multimodal model combining a **native-resolution vision encoder**, a unified image/video encoding strategy, and DSA-based sparse attention for 256K multimodal context, aimed at long-video understanding and agentic tasks — *source:* https://arxiv.org/abs/2606.10651 and https://www.alphaxiv.org/abs/2606.10651 — *quality:* gold (arXiv preprint technical report; abstract/summary read via search snippet, not full PDF).

2. **Encoder-free / "pixel-direct" designs — a real but still-minority alternative, with one notable move from research-only to a mid-sized shipped model.** The general shape (Fuyu, EVE, Chameleon, Mono-InternVL, NEO — mostly 2024-era research models using patch-embedding layers instead of a pretrained ViT) is not new. What is new/notable in-window:
   - **Tuna-2** ("Pixel Embeddings Beat Vision Encoders for Multimodal Understanding and Generation") — arXiv:2604.24763, i.e. **April 2026** (just before the window, flagged) — argues pixel embeddings can replace pretrained vision encoders — *source:* https://arxiv.org/pdf/2604.24763 — *quality:* gold (arXiv preprint; abstract-level read only).
   - **Gemma 4 12B (Google)** — released **June 3, 2026** — described as "the first medium-sized, encoder-free multimodal model," natively ingesting text, image, audio, and video **without separate encoder networks**, 256K-token context window, Apache 2.0 license — *source:* https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemma-4-12b/ and https://developers.googleblog.com/gemma-4-12b-the-developer-guide/ and https://www.techtimes.com/articles/317758/20260604/google-gemma-4-12b-brings-multimodal-ai-16gb-laptops-free-under-apache-20.htm — *quality:* silver-to-gold (Google's own developer blog is close to a primary source; not independently fetched, so treated as silver pending direct verification). **This is the single strongest piece of evidence in this sweep that encoder-free designs are moving from academic-only into mainstream-lab mid-sized releases** — Google shipping a 12B encoder-free model just 3-4 weeks before the survey's freeze date is a meaningful signal that the survey's "current practice" claim (if it asserts the encoder+projector stack as unchallenged in production) may already need a caveat, even measured strictly against the 2026-06-28 freeze. Whether this constitutes "displacement" of the CLIP+MLP+LLM stack, or a coexisting alternative for edge/on-device use cases, is not resolved by the sources found — reported honestly as an open question, not asserted either way.

3. **Mixture-of-experts vision towers — remains research-stage, NOT evidence of a production trend.** Search results turned up only 2023-2025-dated papers (MOVE / arXiv:2502.15381, ViMoE / arXiv:2410.15732, "Rethinking the Mixture of Vision Encoders Paradigm" / arXiv:2501.06986) proposing MoE-style routing *among vision encoders themselves*. No evidence was found of a shipped/production model in the 2026-05..08 window that puts the *vision tower* itself behind MoE routing. This is distinct from — and should not be conflated with — the well-established practice of an MoE **LLM decoder** paired with a dense vision encoder, which multiple 2026 models use (DeepSeek-VL2, Kimi K3, Kwai Keye-VL-2.0-30B-A3B all pair a dense-ish vision front-end with an MoE *language* backbone). **Honest null result: no evidence of vision-tower MoE reaching production in this window** — *source (negative finding basis):* search snippets for "mixture-of-experts vision encoder 2026" surfaced only pre-2026 or non-vision-specific MoE papers — *quality:* n/a (absence-of-evidence claim, not a positive citation).

**Overall Q3 verdict for the survey:** the early-fusion CLIP-encoder + MLP-projector + LLM stack is **not displaced** as of this sweep — it is still what most large/flagship 2026 open and closed multimodal models use (Kimi K3, GLM-4.6V, LFM2.5-VL-3B, Gemini/GPT/Claude families as far as documented). But native-resolution encoders continue consolidating as the *within-paradigm* standard (not new since June), and encoder-free designs took one concrete step toward mainstream viability via Gemma 4 12B. Vision-tower MoE is a non-finding (no production evidence). This should be reported to the survey as "trend continuation + one notable data point," not as a paradigm shift.
