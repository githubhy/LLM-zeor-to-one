## <a id="sec-C"></a>C Connector derivations

<a id="p-c-connector-derivations-1"></a><!-- para:c-connector-derivations-1 --> **Depth tier:** headline

<a id="p-c-connector-derivations-2"></a><!-- para:c-connector-derivations-2 --> This appendix completes the two connectors § <!-- secxref:3.3 -->[§3.3](architecture-building-blocks.md#sec-3.3)–<!-- secxref:3.4 -->[§3.4](architecture-building-blocks.md#sec-3.4) introduced but did not fully derive: BLIP-2's Q-Former, whose three pretraining objectives share one set of queries by switching attention masks, and Flamingo's gated cross-attention, whose stability rests on a single zero-initialized scalar.

<!-- sec:C.1 -->
### <a id="sec-C.1"></a>C.1 The Q-Former's three objectives

<a id="p-c1-the-q-formers-three-objectives-1"></a><!-- para:c1-the-q-formers-three-objectives-1 --> BLIP-2 <!-- cite:4 -->[[4]](#ref-4) uses "32 queries where each query has a dimension of 768 (same as the hidden dimension of the Q-Former)", initializes the module "with the pre-trained weights of $\text{BERT}_{\text{base}}$, whereas the cross-attention layers are randomly initialized" and inserted "every other transformer block", and reports that "in total, Q-Former contains 188M parameters" with the queries themselves counted as parameters <!-- cite:4 -->[[4]](#ref-4). It pretrains those queries with three objectives that share input format and weights and differ *only* in the self-attention mask between queries and text — the mask is how one module learns three behaviors.

<a id="p-c1-the-q-formers-three-objectives-2"></a><!-- para:c1-the-q-formers-three-objectives-2 --> **The bottleneck is severe, and that is the design.** Counting in tokens, which is the currency the LLM actually pays in: a $224$-pixel image at patch size $14$ yields $(224/14)^2 = 256$ patch tokens (<!-- secxref:2.2 -->[§2.2](fundamentals.md#sec-2.2)), and the Q-Former emits $32$ — an $8\times$ reduction, and a far larger one at the higher input resolutions later models use. Every downstream claim about the Q-Former's efficiency, and every complaint about its fine-grained-detail failures (<!-- secxref:10 -->[§10](comparison-and-tradeoffs.md#sec-10)), traces to that ratio. The connector is an information bottleneck by construction, and what does not fit through the $32$ queries is not recoverable downstream, because the frozen image encoder is never consulted again — the LLM sees the summary, never the image.

<a id="p-c1-the-q-formers-three-objectives-3"></a><!-- para:c1-the-q-formers-three-objectives-3 --> **Image-Text Contrastive (ITC).** Align the query outputs $\mathbf{Z}\in\mathbb{R}^{32\times d_q}$ with the text's `[CLS]` representation $t$. Because there are $32$ query vectors but one text vector, the image-text similarity is the *best-matching* query:

<a id="eq-1"></a><!-- eq:C-1 -->
$$
s(I,T) = \max_{m\in\{1,\dots,32\}} \mathrm{sim}(\mathbf{z}_m,\, t) \tag{1}
$$

<a id="p-c1-the-q-formers-three-objectives-4"></a><!-- para:c1-the-q-formers-three-objectives-4 --> trained with an InfoNCE objective (§ <!-- secxref:B -->[§B](appendix-b-contrastive-infonce.md#sec-B)) over in-batch negatives — affordable because the frozen encoder lets many samples fit per device, so no momentum queue is needed. A *unimodal* mask forbids queries and text from attending to each other, preventing information leakage that would trivialize the matching.

<a id="p-c1-the-q-formers-three-objectives-5"></a><!-- para:c1-the-q-formers-three-objectives-5 --> **Image-grounded Text Generation (ITG).** Train the queries to extract the visual information *needed to generate* the caption. Since the queries are the only bridge to the frozen image features, forcing them to support generation makes them capture caption-relevant content. A *multimodal-causal* mask lets queries attend to each other (but not to text), and each text token attend to all queries and the preceding text — the causal structure of generation, with the image available throughout.

<a id="p-c1-the-q-formers-three-objectives-6"></a><!-- para:c1-the-q-formers-three-objectives-6 --> **Image-Text Matching (ITM).** A binary "is this pair matched?" classifier. A *bidirectional* mask lets all queries and text tokens see each other, so each output query embedding is multimodal; a two-class head scores each, and the logits are averaged. Hard-negative mining (pairs the ITC stage found confusable) sharpens the decision. The three masks turn one $32$-query module into a contrastive aligner, a conditional generator, and a matcher — the bottleneck $\mathbf{Z}$ of § <!-- secxref:3.3 -->[§3.3](architecture-building-blocks.md#sec-3.3) (Eq 2 there) is what all three squeeze the image through.

### <a id="sec-C.2"></a>C.2 The Perceiver Resampler as cross-attention

<a id="p-c2-the-perceiver-resampler-as-cross-attention-1"></a><!-- para:c2-the-perceiver-resampler-as-cross-attention-1 --> Flamingo's resampler <!-- cite:3 -->[[3]](#ref-3) (<!-- secxref:3.3 -->[§3.3](architecture-building-blocks.md#sec-3.3)) is a cross-attention block with a twist: the *queries* are a fixed bank of $M$ learned latent vectors $\mathbf{L}$, and the *keys and values* are the variable-length visual features $\mathbf{X}$ concatenated with the latents themselves.

<a id="p-c2-the-perceiver-resampler-as-cross-attention-2"></a><!-- para:c2-the-perceiver-resampler-as-cross-attention-2 --> Concretely, the resampler "takes as input a variable number of image or video features from the vision encoder and produces a fixed number of visual outputs (64)", so $M = 64$; it runs $6$ layers at width $1536$ with $16$ heads, and — the detail worth pausing on — it holds those dimensions **constant at $194$M parameters across Flamingo-3B, 9B, and 80B** <!-- cite:3 -->[[3]](#ref-3). The resampler does not scale with the model. Whatever summarizing an image requires, Flamingo's authors concluded it is a fixed-size job, independent of how large a language model will consume the result — which is a substantive architectural claim, not a tuning convenience, and it is the assumption that a native-resolution design (<!-- secxref:3.4 -->[§3.4](architecture-building-blocks.md#sec-3.4)) rejects.

<a id="p-c2-the-perceiver-resampler-as-cross-attention-3"></a><!-- para:c2-the-perceiver-resampler-as-cross-attention-3 --> The key/value concatenation is a deliberate departure the paper flags: "Unlike in DETR and Perceiver, the keys and values computed from the learnt latents are concatenated to the keys and values obtained from $X_f$, which we found to perform slightly better" <!-- cite:3 -->[[3]](#ref-3). The mechanism is that each latent can attend to *what the other latents have already gathered* as well as to the raw features, which lets the bank divide labour — a latent can specialize by conditioning on its neighbours rather than duplicating them. Note the epistemic status the source itself assigns: "slightly better", with no ablation number attached. Treat it as a reported implementation choice, not a demonstrated principle. *[reported]* The output inherits the query bank's shape $M\times d_v$, so however many features arrive, exactly $M$ come out — the learned down-sampler of <!-- secxref:3.3 -->[§3.3](architecture-building-blocks.md#sec-3.3). For video, the spatio-temporal feature grid (frames at $1$ FPS, with learned temporal embeddings) is flattened into $\mathbf{X}$ before resampling, which is why one mechanism handles images and video identically: both are just a variable-length set of vectors to be summarized into $M$.

### <a id="sec-C.3"></a>C.3 Gated cross-attention dense, in full

<a id="p-c3-gated-cross-attention-dense-in-full-1"></a><!-- para:c3-gated-cross-attention-dense-in-full-1 --> The GATED XATTN-DENSE block of § <!-- secxref:3.4 -->[§3.4](architecture-building-blocks.md#sec-3.4) (Eq 3 there) is inserted *between* each pair of frozen language-model layers, and runs four steps on the running representation $\mathbf{y}$: a gated cross-attention to the visual tokens, a gated dense feed-forward, then the original frozen self-attention and feed-forward. The two new sublayers are scaled by $\tanh(\alpha)$ with per-layer learnable scalars $\alpha$ initialized to zero, so at initialization $\tanh(0)=0$ makes both new sublayers vanish and the block is the identity — the conditioned model reproduces the frozen LM exactly (<!-- secxref:3.4 -->[§3.4](architecture-building-blocks.md#sec-3.4) worked example). As training proceeds each layer opens its gate independently, and because the gate is *per-layer*, the model learns *where* in its depth to admit visual information rather than being forced to use it uniformly. The cost, as <!-- secxref:3.4 -->[§3.4](architecture-building-blocks.md#sec-3.4) noted, is that these blocks are many new parameters and the frozen LM cannot adapt its own weights to vision — it can only react through the gated ports. This is the deep-fusion counterpart to the Q-Former's bottleneck: where BLIP-2 compresses the image into a soft prompt the LM reads at its input, Flamingo leaves the image uncompressed and lets the LM *reach out* to it at every layer.

<a id="p-c3-gated-cross-attention-dense-in-full-2"></a><!-- para:c3-gated-cross-attention-dense-in-full-2 --> **The zero-init rests on an exact-identity argument, and it is worth stating as one.** The block computes $\mathbf{y} \leftarrow \mathbf{y} + \tanh(\alpha_{\text{xattn}})\cdot\mathrm{attn}(q{=}\mathbf{y}, kv{=}\mathbf{x})$ then $\mathbf{y} \leftarrow \mathbf{y} + \tanh(\alpha_{\text{dense}})\cdot\mathrm{ffw}(\mathbf{y})$, with both scalars initialized at $0$ <!-- cite:3 -->[[3]](#ref-3). Since $\tanh(0) = 0$ exactly — not approximately — every new sublayer contributes the zero vector on the first forward pass, and the composed network is *pointwise identical* to the frozen language model, for every input. The paper's stated goal is precisely this: "to ensure that at initialization, the conditioned model yields the same results as the original language model" <!-- cite:3 -->[[3]](#ref-3). Two things follow that a merely-small initialization would not give. The multimodal model *starts* at the frozen LM's full text competence rather than at a perturbation of it, so nothing has to be recovered; and $\tanh'(0) = 1$, the largest the derivative ever gets, so the gate sits at its point of maximum sensitivity and can open quickly. Zero-init is the unique choice with both properties — it is the only value that is simultaneously an exact identity and a maximum-gradient point.

<a id="p-c3-gated-cross-attention-dense-in-full-3"></a><!-- para:c3-gated-cross-attention-dense-in-full-3 --> The ablation is unusually clean. Removing the gating costs "a drop of 4.2% in our overall score", and — the part that matters more than the score — "disabling the 0-initialized tanh gating leads to training instabilities" <!-- cite:3 -->[[3]](#ref-3). A mechanism that is justified by an identity argument and then shown to cause divergence when removed is about as well-evidenced as an architectural choice in this literature gets. *[established]*

### <a id="sec-C.4"></a>C.4 What "freezing the LM" actually saves, by scale

<a id="p-c4-what-freezing-the-lm-actually-saves-by-scale-1"></a><!-- para:c4-what-freezing-the-lm-actually-saves-by-scale-1 --> Deep fusion is routinely described as parameter-efficient because the language model is frozen. Flamingo's own parameter table shows that framing is scale-dependent, and at small scale it is close to false. The gated layers are inserted at every block for Flamingo-3B, every fourth for 9B, and every seventh for 80B <!-- cite:3 -->[[3]](#ref-3), which yields:

| Model | Frozen LM | Trainable gated layers | Gated / frozen | Trainable share of total |
|---|---|---|---|---|
| Flamingo-3B | $1.4$B | $1.2$B | $86\%$ | $44\%$ |
| Flamingo-9B | $7.1$B | $1.6$B | $23\%$ | $19\%$ |
| Flamingo-80B | $70$B | $10$B | $14\%$ | $13\%$ |

<a id="p-c4-what-freezing-the-lm-actually-saves-by-scale-2"></a><!-- para:c4-what-freezing-the-lm-actually-saves-by-scale-2 --> At $3$B the "frozen" model trains almost as many new parameters as the language model contains, so the memory saved by freezing is roughly halved by the machinery added to exploit it; only at $80$B does the arrangement look like the parameter-efficient adaptation it is usually described as. The trend is a direct consequence of the insertion schedule — inserting every block versus every seventh is a $7\times$ difference in added layers — and the schedule was itself chosen to keep the added cost tolerable at scale. **The lesson generalizes past Flamingo: "we freeze the backbone" bounds what you update, not what you must store or train, and the two diverge most exactly where compute is scarcest.** This is the quantitative form of the tradeoff <!-- secxref:10 -->[§10](comparison-and-tradeoffs.md#sec-10) states qualitatively, and it is why BLIP-2's $\sim$$188$M trainable parameters against Flamingo-80B's $10.2$B — the "$54\times$ fewer trainable parameters" of BLIP-2's abstract <!-- cite:4 -->[[4]](#ref-4), which reproduces exactly as $10{,}200/188 = 54.3$ — is a comparison of two genuinely different design philosophies rather than two tunings of one.

### <a id="sec-C.5"></a>C.5 One image at a time: a result that should be more surprising than it is

<a id="p-c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-1"></a><!-- para:c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-1 --> In an interleaved image-text sequence, which images should a text token be allowed to attend to? The obvious answer is *all preceding ones*: more context cannot hurt, and a model that can compare two images should outperform one that cannot. Flamingo restricts each text token to attend to **only the single most recent image**, formalized by a map $\phi$ sending each text position to the index of the last image before it <!-- cite:3 -->[[3]](#ref-3). The ablation runs the obvious answer against it, and the obvious answer loses by $7.2$ points of overall score ($70.7$ against $63.5$) <!-- cite:3 -->[[3]](#ref-3).

<a id="p-c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-2"></a><!-- para:c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-2 --> Note first what the restriction does *not* cost: "the dependency on all previous images importantly remains via self-attention in the LM" <!-- cite:3 -->[[3]](#ref-3) — earlier images have already deposited their influence into the text representations, so information is routed rather than discarded. The paper's explanation for why less direct access wins is that "when attending to all previous images, there is no explicit way of disambiguating between different images in the cross-attention inputs" <!-- cite:3 -->[[3]](#ref-3): a flat key/value set of two images' tokens is a *bag*, with nothing marking which token came from which image, so the model must infer a binding the architecture never encoded. Restricting to one image makes the binding trivially unambiguous. The authors report trying the direct fix — index tags and learned per-image embeddings — and finding it "not as robust ... when the number of images per sequence changes between training and test time", which for Flamingo is the whole point, since it trains at five images per sequence and evaluates at up to thirty-two <!-- cite:3 -->[[3]](#ref-3).

<a id="p-c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-3"></a><!-- para:c5-one-image-at-a-time-a-result-that-should-be-more-surprising-than-it-is-3 --> The generalizable point is that **an architectural restriction can outperform its own relaxation when the relaxation introduces an ambiguity the model has no mechanism to resolve** — the failure is not a shortage of capacity or context but a missing binding between a feature and its source. That is the same defect M-RoPE addresses for video by giving every token an explicit temporal coordinate (<!-- secxref:F.6 -->[§F.6](appendix-f-audio-video.md#sec-F.6)), and it is worth carrying into any design that concatenates features from several sources into one attention pool. *[established]*

### <a id="sec-C.6"></a>C.6 Two parameter counts that do not reconcile

<a id="p-c6-two-parameter-counts-that-do-not-reconcile-1"></a><!-- para:c6-two-parameter-counts-that-do-not-reconcile-1 --> Both connector papers report trainable-parameter counts that disagree with themselves, and since the comparison between them is *conducted in those counts*, the discrepancies are recorded here rather than silently averaged.

<a id="p-c6-two-parameter-counts-that-do-not-reconcile-2"></a><!-- para:c6-two-parameter-counts-that-do-not-reconcile-2 --> BLIP-2 states that "Q-Former contains 188M parameters" and its headline table reports $188$M trainable, but its per-configuration table lists $103$–$108$M trainable for every individual ViT/LLM combination, none of which is $188$M <!-- cite:4 -->[[4]](#ref-4). The paper does not reconcile the two. The $54\times$ headline claim is computed against the $188$M figure, which is the *larger* of the two candidates and therefore the one least flattering to BLIP-2; on the per-configuration counts the ratio would be near $100\times$. The inconsistency thus understates the paper's own claim, which is the benign direction for it to err. Flamingo's table lists $1.2$B and $1.6$B trainable gated-layer parameters for its 3B and 9B models while its appendix prose states $1.4$B and $1.8$B for the same models, each $0.2$B higher; the two agree exactly at $10$B for the 80B model <!-- cite:3 -->[[3]](#ref-3). The <!-- secref:C.4 -->[§C.4](#sec-C.4) table uses the tabulated figures throughout, so its ratios are internally consistent; substituting the prose figures moves the $3$B row from $86\%$ to $100\%$, which strengthens that section's conclusion rather than weakening it. Neither discrepancy changes any comparison in this survey, and both would change a reader's arithmetic if they reproduced it — which is the reason to say so.
